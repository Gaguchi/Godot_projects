## 1. Diagnosis: why the current map floats (root causes, ranked)

The map fails on **integration**, not asset quality. Seven research angles converge on the same verdict: the interactive layer and the backdrop layer were authored independently, in incompatible visual spaces, with no shared light, palette, value plan, or geometry. Ranked by leverage to fix:

1. **The backdrop is decoupled from node placement (the root cause).** `PaperMap.tsx` seeds an *independent* deterministic biome grid (`biomeGrid(cols, rows, seed)`, `CELL = 76`) that knows nothing about where the 15 nodes sit (x 100–760, y 150–620 in a 2120×700 strip). Terrain symbols scatter on a grid; nodes scatter on hand-authored coordinates; they never reference each other. FTL, Banner Saga, and Battle Brothers all bind terrain and nodes — settlements sit in painted clearings, roads carve the land between them ([Battle Brothers Dev Blog #7](https://battlebrothersgame.com/blog-post-7-worldmap/)). Every other fix is lipstick until this is reversed. **Note the geometry precisely:** the 15 nodes occupy only x∈[100,760] / y∈[150,620] — a ~660×470 cluster in the upper-left ~31% of the 2120-wide strip. So the "camera pans left→right across the journey" signature is *currently false* — the camera barely moves. This must be resolved before any art is authored (see §5 step 1).

2. **Two mutually-cancelling art directions are stacked.** `OverworldScene.tsx` paints a dark-fantasy *atmospheric void* (amber radial bloom + `feTurbulence` grain + fog + vignette, lines 532–571), while `PaperMap.tsx` overlays an *antique-parchment ink cartograph* (sepia hatching `#5b4126`, compass rose, burnt-edge vignette, ink tree/mountain symbols, double border). Painterly-void and ink-on-vellum are different languages fighting on one surface. Pick one.

3. **No value staging → no depth → "floating in space."** The backdrop is a near-uniform mid-dark vertical gradient (`sky → base → ground`) with equal-contrast grain everywhere. A real illustrated map reads ground receding via a **value/saturation gradient front-to-back**; flat top-down terrain makes atmospheric perspective literally *impossible* ([Vaia — atmospheric perspective](https://www.vaia.com/en-us/explanations/art-and-design/painting-techniques/atmospheric-perspective/)). **Critically, value structure cannot be left to the SDXL prompt** (see §4) — it must be a runtime composite owned in code.

4. **Nodes have no contact shadow or carved seat.** Each node is a `38px` parchment disc + ink ring drawn at full opacity on a flat field (lines 724–728). A symmetric `box-shadow` reads as "glowing object floating"; grounding requires an *offset, squashed contact ellipse* sitting on a surface ([ImageWork — contact vs drop shadow](https://imageworkindia.com/contact-shadow-vs-drop-shadow-photoshop/); [VectorStorm — blob shadows](https://www.vectorstorm.com.au/2012/05/15/lets-talk-about-shadows/)). This is the single cheapest, highest-FEEL fix and needs **zero art** — do it first.

5. **Roads read as wireframe.** Despite the `ROAD` table's intent (line 120), `shadowW: 0` everywhere (verified lines 124–127) — the comment promises a ditch shadow + dirt body that the code never draws. Each edge is one dashed sepia stroke + a parchment halo (lines 651–661). A single flat stroke with no offset under-shadow, no width taper, and no relationship to painted ground *is* the wireframe tell ([ESRI — casing](https://www.esri.com/arcgis-blog/products/arcgis-pro/mapping/make-lines-legible-and-pop-with-casing)).

6. **No projection match.** A painted backdrop implies a camera (horizon, ground plane); a flat-orthographic vector disc + 2px line has none. The eye reads two incompatible spaces stacked — the #1 "pasted-on" cause.

7. **Procedural tiling/noise has no focal hierarchy.** `feTurbulence` grain is equally busy everywhere, so nodes fight the terrain instead of resting in quiet clearings; the eye has nowhere to land.

**One-line thesis (port this):** the map floats because a *flat-orthographic vector UI* sits on *independently-generated, washed-out, perspective-implying procedural terrain* with no shared light, palette, value plan, baked sockets, or carved roads. The fix is one coherent plane: a value-staged painterly band whose quiet clearings are *reserved from the node graph*, with grounded discs (contact shadows), carved roads (casing), and glow reserved for state.

**On the FTL benchmark — read this correctly.** The user named FTL's beacon map as the *achievable bar*, and that framing must be corrected before it misleads the art direction. FTL does **not** paint bespoke per-sector vistas carved to its node layout. FTL places beacons on a **6×4 grid, ~80% chance per cell with jitter** ([FTL Wiki: Sectors](https://ftl.fandom.com/wiki/Sectors)) and renders them as **plain colored dots** — sand-yellow unexplored → blue explored ([FTL Wiki: Beacons](https://ftl.fandom.com/wiki/Beacons)) — over a **single generic per-sector-*type* starfield/nebula** that is *not* authored per-layout. FTL reads as grounded for three transferable reasons, none of which is "painted terrain": (a) the fiction is **space**, so floating dots are diegetically correct; (b) the nodes carry **100% of the meaning** via high-contrast color/state on a dark field; (c) **glow is reserved for state**, never decoration. The lesson to port from FTL is *cheap, robust, state-carries-everything* — **not** "paint vistas." The painterly-terrain prescription below is the **Banner Saga / Battle Brothers** bar, which is *higher* than FTL. We own that explicitly: we adopt FTL's discipline (dark field, state-carried hierarchy, glow-as-scalpel) and layer a Banner-Saga painterly ground *only* to the extent the GPU budget proves it out (§4). If the painterly bake fails to prove out, the FTL discipline alone — applied to ALT B / a stylized flat field — still ships a grounded map.

## 2. Recommended Art Direction (RECOMMENDED + 2 ALTERNATIVES)

> **Decision rule baked in:** the headline direction is **terrain-only painterly backdrop + SVG-owned roads/sockets** — *not* "bake everything." Baking the road and per-node sockets into the PNG was rejected because (a) the upscaler re-interprets edges at low denoise, so a baked trail will *not* register with `edgePath()`'s spline → visible double-road; and (b) it hard-couples the art to exact node coordinates, breaking the JSON-authored-maps workflow the codebase is built on (edges are computed at runtime from `MAPS` JSON). The backdrop's only job is a **value-staged painterly ground with quiet, reserved clearings** (the depth map flattens those zones); SVG owns every road, socket, contact shadow, and beacon. This keeps node edits a JSON change, never a re-bake.

### ★ RECOMMENDED — "Hearth-Lit Diorama" (painterly ¾-oblique vista, one bespoke terrain-only painting per region; roads + sockets + value mask owned by the React/SVG/Canvas layer)

**Description.** Retire the parchment cartograph entirely (or demote it to a separate fold-out UI artifact). Each region becomes **one composed painterly landscape in ¾ oblique** — a low-angle "diorama landscape" with a horizon at ~y=180, a hazed sky/massif band above it, and a receding ground plane below. The backdrop is generated in ComfyUI with a **depth map authored from the real node data that flattens the clearings where nodes sit** (so the terrain *reserves quiet space* for the graph) — but the **road, sockets, contact shadows, and a node-derived value/darkening mask are drawn at runtime by SVG/Canvas**, never baked. The React/SVG layer is the grounding system; the painting is only the lit ground it sits in.

**Feel.** A dark-fantasy land you march across: warm hearth-light pooling on the lit midground where nodes live, cool low-key shadow everywhere else, a destination glinting on the hazed horizon. Banner Saga's caravan strip with Darkest Dungeon's chiaroscuro — but the chiaroscuro is **composited in code from node positions**, not prayed out of the model.

**Tradeoffs.** Highest art cost and the only direction gated on **unbuilt Stage-0 tooling** (control-image + depth-map rasterizer + a ControlNet/upscale workflow that does not exist yet — see §4/§5). It is the only option that fixes root cause #1 by construction (clearings reserved from the node graph) and matches the Banner-Saga bar. Mitigation: it is sequenced *behind* the zero-art grounding fixes and gated on a single proof bake, so its risk is contained (§5).

**ComfyUI effort.** Realistically a **half-day per region of babysat, sequential bakes** (not "15–30 min"): depth-only base → unload → upscale → optional refine, with hand-rejection of bakes whose light isn't low-left, plus expected black/failed retries on the 1660 (§4). One-time, reused across the whole game.

**Why this wins (when it proves out).** (a) **FTL discipline** — beacons as bright points on a value-staged dark field, glow reserved for state; (b) **Forged & Lit** — single low warm key, local hearth pools, no dead gray ([pointnthink — Darkest Dungeon](https://www.pointnthink.fr/en/the-art-of-darkest-dungeon/)); (c) **6 GB GPU** — a terrain-only PNG is an offline bake, and tiled generation keeps VRAM constant *in isolation* ([Apatero low-VRAM guide](https://www.apatero.com/blog/complete-comfyui-low-vram-survival-guide-2025)) — provided the heavy subsystems are run as **separate sequential graphs, never co-resident** (§4).

### ALT A — "Polished Parchment" (keep the cartograph, commit to it fully) — **the designated fallback**

**Description.** Lean *into* `PaperMap.tsx` as the sole language: one bespoke aged-parchment sheet per region, ink terrain hand-tuned around node positions, roads as proper cartographic double-lines (dotted = trail/planned, solid = traveled), a diegetic war-table/leather frame holding the HUD.

**Feel.** Banner-of-the-realm campaign table; cohesive, cheap, never "AI slop" because it's flat-by-design (Slay-the-Spire-style flat dark ground where icon glow carries hierarchy).

**Tradeoffs.** Lowest risk, lowest GPU cost (mostly SVG/CSS, minimal-to-no ComfyUI). It abandons the painterly Forged-&-Lit "real place" feel — it's a *map of* a place, not a place. **This is the explicit fallback** if the Stage-0 proof bake (§5 step 3) fails: it resolves the parchment/void conflict by deleting the painterly half rather than the parchment half, and most of it is already built.

**ComfyUI effort.** Low — optional parchment-texture/stain bakes only; could ship pure SVG/CSS.

### ALT B — "Lit Tabletop" (high-oblique near-top-down board-game plane) — **the true FTL-bar option**

**Description.** Bake a **near-top-down "tabletop map" plane** (minimal perspective) so painted ground and the flat node graph share one space. Sockets and roads owned by SVG; depth restricted to a thin parallax sky band fenced off by a horizon line so nodes never sit "in" deep space.

**Feel.** Closest to literal FTL — a flat authored plane, bright points on a dark field, no projection mismatch to manage. This is the option that actually matches the *FTL discipline* the user named (cheap, robust, state-carries-hierarchy), as opposed to the higher Banner-Saga bar of the recommendation.

**Tradeoffs.** Less cinematic than the diorama; the horizontal camera-pan gains less from parallax. Still needs a bespoke per-region bake, but with **far simpler prompts** (less perspective to coax from SDXL — a real plus on the 1660) and **no projection-match risk**. If the recommendation's oblique vista fights the anime checkpoint (a live risk — §4), this is the graceful step-down *before* falling all the way back to ALT A.

**ComfyUI effort.** Medium — same separated-graph pipeline, simpler/flatter prompts.

**Decision:** Sequence toward the **Hearth-Lit Diorama**, but do **not** commit the full build to it up front. Ship the zero-art grounding fixes first (they fix "floating" on the *existing* backdrop regardless of direction), then gate the diorama on one Borderlands proof bake. **If the bake proves out → diorama. If the oblique vista fights the checkpoint → step down to ALT B (Lit Tabletop), the true FTL-bar option. If depth-controlled clearings don't reserve reliably at all → fall back to ALT A (Polished Parchment).** All three share the same SVG-owned road/socket/beacon grounding layer, so the fallback cost is only the backdrop, never the interactive system.

## 3. Rendering Architecture (React 19 + SVG + Canvas, 1280×720)

> **Resolve the strip-width question first (gates everything here).** The nodes cover only ~31% of the 2120 width. **Recommendation: re-author the Borderlands node coordinates to span x≈100→2000** (a cheap JSON edit in `borderlands.json`) so the left→right pan is *real* and a wide backdrop is justified. The alternative — shrinking every backdrop to the used ~900×600 bounds — halves every VRAM/decode number below but concedes the strip's signature pan. Either way, **decide before authoring art or sizing backdrops.** Numbers below assume the re-authored full-width strip; halve them for the shrink option.

**Backdrop strategy.** One bespoke **terrain-only PNG per region** (2120×700 if re-authored full-width), served as a single `<img decoding="async" fetchpriority="high">` (or CSS `background-image`), **never blitted to canvas per frame** ([MDN — optimizing canvas](https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API/Tutorial/Optimizing_canvas)). A 2120×700 RGBA decodes to ~5.9 MB regardless of file size — **decode only the current region, drop the others**; pre-decode the next region's PNG *before* a transition to avoid frame spikes ([three.js forum](https://discourse.threejs.org/t/how-to-handle-2k-4k-panorama-texture-tils-uploads-without-frame-spikes/87793/7)).

**Layer stack (bottom → top).** The stage is **CSS-scaled** (1280×720 → fit), so the compositor resamples every large layer each frame the camera moves — on a 1660-class machine a 4-PNG parallax stack with `will-change` on each (every layer gets its own backing store) is real jank. **So cap the backdrop to the hero PNG + at most two thin CSS-translate bands** (sky + one massif); do *not* ship 3–4 full backdrop PNGs per region. The **gameplay plane stays at multiplier 1.0** so node coordinates and hit-testing remain correct:

| Layer | Content | Pan multiplier | Tech |
|---|---|---|---|
| Sky band (thin) | far haze, top ~25% | 0.15 | one `<div>` translate3d, CSS gradient or thin PNG |
| Massif band (thin) | one horizon silhouette strip (cool, desaturated) | 0.35 | one thin `<img>` translate3d |
| **Backdrop hero** (terrain only) | the painterly ground PNG | **1.0** | single `<img>` translate3d |
| **Value mask** (node-derived) | multiply-darken + per-node radial lifts | 1.0 | Canvas or SVG, composited from node data |
| Ground-haze seam | warm valley mist at fore/mid seam | 1.0 | CSS gradient div |
| Roads — static casing `<g>` | ditch/bank/body, filtered ONCE | 1.0 | SVG, static |
| Roads — dynamic state `<g>` | dash/glow/active hop, unfiltered | 1.0 | SVG, animated |
| Nodes + contact shadows + glows | the 15 markers | 1.0 | SVG/DOM (current Pressables) |
| Fog/reveal | explored mask | 1.0 (in pan layer) | Canvas, event-driven |
| Token + follower silhouettes | caravan walking the path | 1.0 | DOM/SVG, rAF |
| Vignette/framing | asymmetric bottom/left-keyed | screen-fixed | CSS overlay |
| HUD | `GameHud`, route planner | screen-fixed | DOM |

Decorative bands are **sibling divs reading the same `camera` state × multiplier** — additive to the existing `transform: translate(${camera.x}px, ...)`. Round `camera.x` to integers, prefer `translate3d` on a *single* hero image over a multi-layer `will-change` stack, and verify pan smoothness on a **1660-class machine, not the dev box**.

**The node-derived value mask (this is how value staging is *guaranteed*, not hoped).** SDXL on an anime checkpoint + pixel LoRA tends to flat, evenly-lit, high-key output — the opposite of the chiaroscuro the "greyscale gate" demands; a flat-gray depth map controls *geometry, not luminance*. So **do not rely on the prompt for value structure.** Bake the terrain relatively flat, then composite an **authored value mask in the React/Canvas layer, computed from node positions**: a global multiply-darkening vignette plus a soft additive radial *lift* at each node. This makes the 3-value plan deterministic and **node-coupled by construction**, and re-uses data you already have. The acceptance gate still applies: desaturate the *composited* result to greyscale — if you can't instantly tell nodes from terrain, tune the mask (not the prompt). This also subsumes the old "quiet clearings" requirement: the mask both darkens negative space and lifts the clearings.

**Road rendering (the chosen hybrid — SVG owns the road entirely).** The road is **not** baked into the PNG (registration drift + node-coupling, per §2). Instead, split **texture (static, filtered once)** from **state/motion (dynamic, unfiltered)** entirely within SVG ([ESRI casing](https://www.esri.com/arcgis-blog/products/arcgis-pro/mapping/make-lines-legible-and-pop-with-casing); [Smashing — SVG displacement perf](https://www.smashingmagazine.com/2021/09/deep-dive-wonderful-world-svg-displacement-filtering/)). Replace the current single-stroke road (lines 651–661):

- **Static casing `<g>` (filtered once, no animation):** keep `edgePath()` (the seeded quadratic Bézier is good). Stack, bottom→top: (1) **ditch shadow** `w+5`, near-black `rgba(0,0,0,0.35)`, offset **+1.5px down**; (2) **far-bank highlight** `w+3`, warm `#caa766`, offset **−1px up**; (3) **dirt body** `w`, `#5b4126`; (4) **worn centerline** `w*0.4`, lighter dust. Apply a static `feTurbulence`→`feDisplacementMap` worn-edge filter (`type="fractalNoise"`, `baseFrequency` ~0.012, `scale` ≤ stroke width, **expand filter region** `x="-20%" width="140%"` or edges clip). **Restore `shadowW`** in the `ROAD` table — it's `0` today, so grounding never happens. **Delete the `#ecdfbe` parchment halo (line 651)** when the parchment direction is retired, or the new painterly road inherits a cartographer's cream outline.
- **Dynamic state `<g>` (unfiltered, animated):** one clean stroke per edge encoding state via *dash + color*: **planned = dotted amber** (`"2 6"`), **traveled = solid amber**, **active hop = comet** (`"14 9999"`, animate `stroke-dashoffset 0 → -pathLength`), distant = faint. Compute length with `path.getTotalLength()` (Béziers — don't hardcode). **Never animate the filter** — motion lives on this unfiltered layer.
- **Connectivity is the SVG layer's job; terrain is flavor:** only traversable edges get the lit treatment; the backdrop must never paint a path that implies connectivity ([FTL beacon-path thread](https://steamcommunity.com/app/212680/discussions/0/558752449554569220/)).

**Node beacons + states.** Keep the `Pressable` structure; restructure each node as a **3-element grounding stack**: (1) **ground-contact ellipse** — CSS `radial-gradient` ellipse `~34×12px`, offset *below* the disc center, `blur(1.5px)` (cheaper and better than a symmetric `box-shadow`); (2) the disc body; (3) **state glow via `filter: drop-shadow()`** (follows alpha, GPU-composited — reserve heavy `feGaussianBlur`/`feMerge` bloom for the single boss node) ([CSS-Tricks — drop-shadow vs box-shadow](https://css-tricks.com/adding-shadows-to-svg-icons-with-css-and-svg-filters/)). Encode three **orthogonal axes** so states never collide: **type** = `NodeMapSymbol` silhouette + a type-hue swatch (the StS lesson — its #1 failing was all-black look-alike icons; redundant shape+icon+color is mandatory for colorblind support — [StS Map Icons](https://slaythespire.wiki.gg/wiki/Category:Map_Icons); [Filament](https://www.filamentgames.com/blog/color-blindness-accessibility-in-video-games/)); **state glow ring** = current/hover/planned/reachable/distant; **progress** = unvisited (full ink) → visited (desaturated + check) → add a missing **failed** state (cold grey + cross badge, mirroring the visited check). Idle life animates **opacity/glow, not position** — replace `overworldPulse`'s `scale(1.15)` (re-introduces float, line 930) with an expanding **ping ring** (`scale 1→2.1`, `opacity .45→0`), staggered by a per-node hash so they don't pulse in lockstep. **Pin the count at 15** (verified in `borderlands.json`) so the mask/depth rasterizer never drops a node.

**Caravan / you-are-here token.** Upgrade `#player-marker` (a red disc interpolating `left/top`, lines 593–610) two ways. (1) Make it a **distinct vertical object** — a planted banner/pennant with its *own* contact ellipse — so it reads as "a thing standing here," not a flat disc. (2) **Walk the actual road spline**: the current linear `left/top` lerp cuts the corner of the bowed Bézier (confirmed lines 597–601). Sample the real path, but **memoize the sampled polyline once per hop** rather than calling `getPointAtLength()` on the live SVG element every rAF frame (per-frame `getPointAtLength` on many paths is measurably slow in some browsers). Derive facing from the tangent, add a ±1.5px vertical bob for gait, trail 2–3 follower silhouettes at small length-offsets ([Banner Saga Wiki: Travel](https://bannersaga.fandom.com/wiki/Travel)).

**Camera + parallax during travel.** Today the camera snaps to center the current node on arrival (lines 200–207). Change to **continuous follow during the hop** (rAF, no CSS transition, token kept ~45% up and leading slightly in travel direction), settling on arrival. Continuous follow + the two parallax bands converts "teleport between dots" into a journey ([code.tutsplus — parallax](https://code.tutsplus.com/parallax-scrolling-a-simple-effective-way-to-add-depth-to-a-2d-game--cms-21510t)). Optional rest-state mouse parallax (±4–8px on the bands) adds dioramic depth for free.

**Fog / reveal.** Add a Canvas fog layer *inside* the pan layer, sized to `map.width × map.height` (~5.9 MB backing store at 2120×700 — fine, but **release the old canvas/context on region switch or it leaks**): fill warm-dark `rgba(10,8,6,0.82)`, then `globalCompositeOperation='destination-out'` with **soft radial-gradient brushes** at revealed nodes; redraw only on reveal events, tween the reveal radius `0→R` over ~700ms when arriving at a frontier node (pair with a one-shot ping on newly-revealed nodes). Tint the fog per region (`ATMOSPHERE[regionId]`) ([ourcade — fog of war](https://blog.ourcade.co/posts/2020/phaser3-fog-of-war-field-of-view-roguelike/)).

**Framing/vignette.** Replace the *symmetric center* radial vignette (line 569) with an **asymmetric, bottom-and-left-heavy** vignette matching travel direction and the low-left key light. Optionally wrap the stage in a diegetic frame (war-table/leather) that houses the HUD.

**Defeating "pasted-on" (scale/perspective/contact-shadow rules).** (1) **The depth map reserves a flat clearing under every node** (the model paints quiet ground there); **the SVG draws the socket** (darkened depression / stone ring) on top — *not baked*, so node edits don't force a re-bake. (2) **One canonical key-light vector** (warm, low, from the left), enforced not by trusting the prompt but by **hand-rejecting any bake whose light isn't low-left** (§4) and then setting a single `--key-light-angle` CSS custom property to match the *chosen* art; all UI `drop-shadow` offsets derive from that variable so art and UI can't diverge. (3) **Contrast moat**: the node-derived value mask's per-node darkening guarantees figure/ground separation on busy terrain. (4) **Quiet zones**: the depth map under-details terrain where nodes sit; the value mask reinforces it. (5) **No global bloom** — glow is a scalpel reserved for interactive state only ([Grokipedia — bloom fatigue](https://grokipedia.com/page/Bloom_(shader_effect))).

## 4. ComfyUI Asset-Generation Plan

**Hardware reality (the binding constraint, stated honestly).** The GTX 1660 has a broken fp16 path → it needs `--force-fp32`/`--no-half` or it emits black/green images ([andreszsogon — GTX 16xx fix](https://www.andreszsogon.com/fix-stable-diffusion-automatic1111-webui-on-geforce-gtx-16xx/)). But the **fp32 SDXL UNet alone is ~10.4 GB and does not fit 6 GB** ([SynpixCloud SDXL VRAM](https://www.synpixcloud.com/blog/sdxl-fine-tuning-vram-guide)). It only runs at all via `--lowvram` **sequential layer offload to system RAM**, which is inherently slow. Therefore the cardinal rule: **never stack VRAM-heavy subsystems in one graph.** Community guidance is explicit that even on an *8 GB* card you do not begin with "SDXL plus several ControlNet branches, IPAdapter, and upscale in the same workflow" ([AI Pixel Guide](https://aipixelguide.com/en/guides/controlnet-models/)). The brief's earlier "two chained ControlNets + IPAdapter + UltimateSDUpscale, fp32+lowvram" plan would thrash exactly the documented RAM↔VRAM 10× stall it claims to avoid. **Launch flags:** `--force-fp32 --lowvram --disable-smart-memory --use-split-cross-attention`, `PYTORCH_CUDA_ALLOC_CONF=max_split_size_mb:512`, and call the existing `POST /free` (`freeVram()`) **between every stage** so subsystems are never co-resident.

**Decompose into separate sequential graphs — never co-resident:**
1. **Base composition** = **ONE ControlNet only**: **depth via Control-LoRA** (~400–800 MB, vs the ~5 GB full fp32 ControlNet — this is the one memory-responsible choice; keep it). **Drop the scribble ControlNet** — depth alone reserves the flat node plateaus; a second conditioning doubles memory for redundant control. If scribble is ever needed, run it as a *separate* second pass, never chained.
2. **IPAdapter style-transfer** (cross-region consistency) is its **own pass on a clean slate** — it adds a CLIP-vision encode + extra cross-attention and is *not* "free" on fp32+lowvram. `freeVram()` before and after.
3. **UltimateSDUpscale** is its **own graph after a full unload**. Its "VRAM constant per tile" property only holds *in isolation* — true here precisely because nothing else is resident.

**Realistic ceilings & budget.** SDXL's native budget is ~1 MP; 2120×700 (1.48 MP) **cannot** be sampled in one pass (OOM/black) — build it as small composed latent → tiled upscale. Budget **3–10 min per pass, 3–4 sequential passes per region, plus hand-rejection and expected black/failed retries → realistically a half-day of babysitting per region**, not "15–30 min." These are a handful of one-time offline bakes, reused for the whole game — the cost is acceptable *because* it's one-time, but plan the calendar honestly.

**Assets to generate, per region (Borderlands / Thornwood / Ashfall):**

| Asset | Target res | Notes |
|---|---|---|
| Hero backdrop (**terrain only** — no road, no sockets) | full-width 2120×700 (gen ~1024×336 → tiled upscale) *or* ~900×600 if shrink option chosen | the one essential per region |
| (Optional) thin parallax bands | sky band, one massif strip | only the two thin bands §3 allows — not 3–4 full PNGs |
| Caravan/banner token + 2 followers | ~96×128, RemBG `character` kind | walks the road |
| Fog/ember particle sprite | ~64×64 tile | subtle drift layer |

Small UI/node/token art packs into **one sprite atlas**; backdrops stay per-region PNGs (too big to atlas), shipped as compressed WebP/AVIF.

**The node-graph workflow (the "grounded" trick is Stage 0 — and it is unbuilt; this is the real long pole).** **Verified current state:** `template.workflow.json` is `Checkpoint→Lora→KSampler→VAEDecode→(RemBG)→Save` — **no `LoadImage`, no `ControlNetLoader`/`ControlNetApply`, no upscale node.** The `backdrop` *string* exists in `SCENE_KINDS` but today only strips RemBG and forces a **1024×1024** latent (not 1024×336). So "wire a `backdrop` kind" actually means **author a ControlNet-capable workflow graph from scratch + build a control-image rasterizer + a depth-map rasterizer** — and *that*, not the GPU bake, is the long pole. Sequence accordingly (§5).

- **Stage 0 (no GPU) — author a depth map from the real node data.** Reuse the existing SVG/Canvas overworld renderer to rasterize a depth PNG where **road corridor + node clearings are flat mid-gray *plateaus*** (reserving flat ground exactly where the graph needs quiet space). **Author the depth map directly; do not auto-estimate it** (depth estimators fail on flat renders). This is what makes terrain *derive from* the node graph — fixing root cause #1 by construction ([comfy depth docs](https://docs.comfy.org/tutorials/controlnet/depth-controlnet); [Apatero — depth ControlNet](https://www.apatero.com/blog/depth-controlnet-posture-transfer-comfyui-complete-guide-2025)). (We rasterize *only* the depth map — not a road/socket control image — because the road and sockets are SVG-owned and must not be baked.)
- **Stage 1 — base composition latent.** `EmptyLatentImage ~1024×336` (≈3:1), **depth Control-LoRA only** (strength ~0.5–0.7), euler/dpmpp_2m ~28–32 steps CFG 6–7, **Tiled VAE decode** (`cpu_vae` fallback). Optional 3-band `ConditioningSetArea` for sky/mid/ground prompt separation ([ComfyUI area composition](https://comfyanonymous.github.io/ComfyUI_examples/area_composition/)). `freeVram()` after.
- **Stage 2 — tiled upscale to target.** `UltimateSDUpscale` (ESRGAN e.g. `4x-UltraSharp`), **512×512 tiles / 32 pad / mask_blur 14**, `Half Tile Offset Pass`, **denoise 0.18** (low denoise keeps the composition stable across tiles) ([UltimateSDUpscale](https://github.com/ssitu/ComfyUI_UltimateSDUpscale); [Coyote-A FAQ](https://github.com/Coyote-A/ultimate-upscale-for-automatic1111/wiki/FAQ)). `freeVram()` before. *(No baked road/sockets need to "survive" the upscale — they don't exist in the PNG; the upscaler only refines terrain.)*
- **Stage 3 (optional) — denoise-0.1 seam refine.**

**Checkpoint & LoRA — a live feasibility risk, not a footnote.** `comfy-gen.ts`'s `scene` preamble forces **`top-down, overhead view` + `pixel art` + `DFSV1`** (the pixel-sprite LoRA trigger). All three actively fight a painterly ¾-oblique vista: `top-down` contradicts the horizon/oblique framing, and `pixel art`+`DFSV1` will dither a 2120-wide image into muddy pixel-banding that reads *cheap and AI* at 1:1 — the exact failure mode we're fixing. **The `backdrop` kind therefore needs its OWN preamble**, not the inherited `scene` one: **drop `DFSV1` / `pixel art` / `top-down`**; add painterly/oblique/atmospheric-perspective terms. **And confirm `waiIllustrious_v160` (an anime *character* model) can even render painterly landscape** — if it can't, a different landscape-capable checkpoint is required, which is a second model download + its own VRAM/precision profile on the 1660. **This is the most likely feasibility blocker for the painterly look specifically, and it is exactly what the §5 proof bake exists to surface.** If it blocks, step down to ALT B (flatter plane, simpler prompt) or ALT A (no painterly bake at all).

**Light direction — enforce by selection, not by prompt.** SDXL does not reliably honor "low golden-hour sun from left" (lands ~60% of the time; the upscaler can flip local shading). So **make light an acceptance criterion, not a prompt hope: generate several, hand-keep only the bake whose key light is genuinely low-left, reject the rest.** Then set `--key-light-angle` to the *chosen* art. Cheap, deterministic, honest.

**Prompts (one skeleton, swap only biome + palette + light):**
- **Borderlands:** "dark fantasy painted landscape panorama, low golden-hour sun from left, dark foreground grass banks framing, lit rolling grassland midground, dirt road winding left to right, hazed blue-grey distant hills, watchtower silhouette on horizon, atmospheric perspective, painterly, Eyvind Earle / Banner Saga influence." *(No `DFSV1`, no `pixel art`, no `top-down`.)*
- **Thornwood:** deep desaturated green-black, broken canopy god-rays on clearings, near-black trunk silhouettes framing, cold blue-grey mist; heaviest top/side vignette.
- **Ashfall:** charcoal-basalt slashed with ember-orange, bottom-up lava key light, erupting cone on the horizon crowned with the one warm accent; warm-edged ember vignette.

**Relax the negative for vistas.** The existing `SCENE_NEGATIVE` (L58) was tuned for *seamless tiles* and bans the very features a composed vista needs (`trees, forest, river, mountains, buildings, rocks, scenery, landscape, multiple terrains`). Add a separate **`backdrop` negative** that keeps those features but bans `character, person, text, UI, frame, road, path, trail, focal single object, map, minimap, vignette, centered composition` (note: **also negative-prompt `road`/`path`** so SDXL doesn't paint a trail that would fight the SVG-owned road). Wire a new **`backdrop` kind** into `comfy-gen.ts`: its own preamble (above), override the latent to ~1024×336 (currently 1024×1024, L101/L119), accept a `--depth` path → `LoadImage`→`ControlNetApply` (depth Control-LoRA), continue into `UltimateSDUpscale` before `SaveImage` (today it saves node 6 and stops), and bump the ~12-min poll ceiling to ~20 min for the upscale stage.

**Cross-region consistency (three stacked locks, strongest first):** (1) same checkpoint + same negative + same sampler/CFG — the dominant factor; (2) same prompt skeleton, swapping only biome/palette/light; (3) **IPAdapter style-transfer anchored to region 1's finished output, applied as its OWN separate Stage-1 pass for regions 2 & 3** (cheap relative to a 24 GB card, *not* free here — own pass, `freeVram()` around it) ([cubiq IPAdapter_plus](https://github.com/cubiq/ComfyUI_IPAdapter_plus)). Identical *staging* (dark frame → lit mid → hazed back) + identical light logic across all three = one world. **The 3-value plan is enforced at runtime by the node-derived value mask (§3), not by post-processing the bake** — the greyscale gate then tests the *composited* map, and failures are fixed by tuning the mask, which is deterministic and node-coupled.

## 5. Prioritized Change List (highest-leverage first; sequenced to fail fast)

**Phase 0 — decide before any code or art (no implementation):**

1. **Resolve strip width (gates all backdrop sizing):** re-author `borderlands.json` node coords to span x≈100→2000 (makes the pan real — recommended), *or* commit to shrunk ~900×600 backdrops. *(root cause #1 geometry)*

2. **Resolve direction & own the FTL framing:** commit to sequencing toward the painterly diorama **but** with SVG-owned roads/sockets (not baked); name **ALT B (Lit Tabletop)** as the FTL-discipline step-down and **ALT A (Polished Parchment)** as the hard fallback. Kill the parchment/void conflict by deciding which language survives. *(root causes #1, #2)*

**Phase 1 — zero-art grounding fixes (ship today; fix "floating" on the *existing* backdrop; de-risk everything else — if these get it ~70% there, the expensive bake may be unnecessary):**

3. **Ground every node:** offset contact ellipse + replace the `scale(1.15)` pulse with a ping ring. Highest FEEL-per-effort, zero art. *(root cause #4)*

4. **Fix roads to the static-casing + dynamic-state hybrid (SVG-owned):** restore `shadowW`, add offset ditch/bank casing strokes + a static worn-edge filter on one layer, keep dash/comet animation on a separate unfiltered layer; encode planned=dotted / traveled=solid / active=comet; **delete the `#ecdfbe` parchment halo**. *(root cause #5)*

5. **Walk the token along the road spline (memoized polyline, not per-frame `getPointAtLength`) + continuous camera follow**, with 2–3 follower silhouettes — turns hops into a journey. *(travel FEEL)*

6. **Replace the symmetric vignette with an asymmetric bottom/left-keyed one**, add a warm ground-haze seam band, and **lock one canonical `--key-light-angle`** driving all UI shadow offsets. *(root cause #3 / pasted-on)*

7. **State glows via `filter: drop-shadow()` + type-distinct silhouette/color/icon redundancy** (StS legibility lesson); add the missing `failed` node state; pin node count at 15. *(readability/accessibility)*

**Phase 2 — the diorama vertical slice (gated; prove before committing the full build):**

8. **Build the Stage-0 tooling (the real long pole):** the depth-map rasterizer (flat-gray plateaus at road corridor + node clearings, authored from `borderlands.json`), plus a ControlNet+upscale workflow graph authored from scratch (none exists today). *(root cause #1)*

9. **Wire the `backdrop` kind into `comfy-gen.ts` with its OWN preamble** (drop `DFSV1`/`pixel art`/`top-down`; add painterly/oblique terms), relaxed+road-banning negative, ~1024×336 latent, depth Control-LoRA → UltimateSDUpscale, ~20-min poll ceiling. *(roots #1, #3)*

10. **Bake ONE depth-only Borderlands backdrop as the proof + style anchor — hand-reject any bake whose key light isn't low-left.** **Gate:** does `waiIllustrious_v160` render an acceptable painterly oblique vista *and* does the depth map reliably reserve flat node clearings? **If yes → diorama. If the vista fights the checkpoint → step down to ALT B. If clearings don't reserve at all → fall back to ALT A and stop here.** *(decision gate — surfaces the §4 checkpoint risk before any further build)*

**Phase 3 — only after the slice proves out:**

11. **Render the backdrop as a single GPU-composited `<img decoding="async">` + at most two thin CSS-translate parallax bands** (not 3–4 PNGs); decode current region only; pre-decode next region before transition; verify smoothness on a 1660-class machine. *(perf + #3)*

12. **Composite the node-derived runtime value mask** (multiply-darken vignette + per-node radial lifts) — this *guarantees* the 3-value plan deterministically; apply the greyscale gate to the composited result. *(root cause #3, made controllable)*

13. **Canvas fog-of-war** (destination-out soft brushes + arrival reveal tween, region-tinted; release the canvas/context on region switch), then **bake Thornwood + Ashfall** via the locked separated-graph pipeline (IPAdapter style-transfer from Borderlands as its own pass). *(exploration FEEL + cohesion)*
