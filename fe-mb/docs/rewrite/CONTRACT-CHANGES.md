# Engine contract — change log

Append-only. Every change to a SHARED contract file — `game/src/engine/{types,actions,effects,rules}.ts`, any exported signature of a module you do not own, `game/src/engine/flow/runtime.ts`, `game/src/ui/store.ts` — gets an entry here BEFORE the edit lands, in the same commit. `types.ts` is never edited silently. Adding a new export to a module you own needs no entry; changing or removing one that another package imports does.

Entry format:

```
## NNNN — <date> — <package> — <file>
Before: <the old type / signature, verbatim>
After:  <the new type / signature, verbatim>
Why:    <one or two sentences; cite the brief section or the bug>
Affects: <every importer that had to change, or "none">
```

Rules (see CONTRACT.md §9):
1. Never widen a union or add an optional field "for later" — a member lands with its emitter/reader and a test (brief §7.8).
2. Never add `undefined` as a valid state value; absence is `null` (save round-trip, brief §2.14 rule 3).
3. A number moves to `rules.ts` or to content; it never appears as a literal in an engine module (brief §8.13).
4. A change that breaks another package's stub signature is coordinated in the entry's `Affects:` line and fixed in the same commit — the tree is always green.

## 0001 — 2026-09-05 — judge — initial contract

The synthesis of proposals A and B (judgement in CONTRACT-JUDGEMENT.md). Deltas from BOTH proposals worth knowing when reading them:

- `rules.knobs.armorCap` is `'none'` (DECISIONS owner answer), not `'halfMaxHp'`.
- `Effect` is ONE flat union in `effects.ts` (no `DomainEvent`/`PresentationEffect` split, no `AnyEffect`); domain events are ordinary members in lowerCamel (`flagSet`, `questStarted`, `locationArrived`, …).
- `Screen = { kind: ScreenKind }` carries no payload; the Field Report is `run.lastBattle`, the win/loss summary is `state.ledger`, UI chrome is `state.ui`.
- `DeckState` holds `CardInstance{uid, cardId, source, mod}` keyed by `uid` (B's `Record<CardId, …>` collided on duplicate card ids).
- `CombatState.tag` AND `CombatState.origin` both exist (tag = loot row key, origin = routing + label); `BattleTag` includes `'quest'` and `'sim'`.
- `ActiveStatus.expiresAt` is `'ownerTurnStart' | 'ownerTurnEnd'` (A's third point `'turns'` dropped).
- `EnemyAction` is the content shape (`kind attack|heal|buff` + `applyStatus`), adapted by `combat/ai.ts#actionAsPlay`; `Item.effect` is `ConsumableEffect`, adapted by `combat/items.ts#itemAsPlay`.
- `ContentRegistry` is imported from `src/content/index.ts` (fields `overworld`, `enemyAI`, `characters: Character` union, `regions: RegionDef`); `Content` adds `version` + `nodeDistance`.
- Persistence is snapshot-only (`embermarch:run` + `embermarch:meta`); the action log is in-memory on the runtime (`log: true`) and verified by `save/replay.ts`, never written to storage.
- `flow/runtime.ts` and `ui/store.ts` are IMPLEMENTED; everything else under `combat/ run/ procgen/ save/ flow/` and `reducer.ts` is a signature stub (`todo('<module>')`).
