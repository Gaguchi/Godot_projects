## 1. What the finished game IS

A single-run tactical roguelite: you lead a small free mercenary company (start 3 units, cap 6) across ONE hand-authored open-sheet world map of 25-40 nodes with hub towns, traveling in any direction, paying one day and one food per hop and rolling encounters on the road (dialogue, deterministic stat-check events, or a grid battle). Battles are Fire Emblem on a 14x10 grid with Slay-the-Spire cards: every unit's deck IS its equipment (innate class cards + the cards of the items in its two hand slots), damage is fully deterministic (no hit/crit/avoid/triangle), armor is a breakable shield, statuses are fixed numbers, enemies run authored role AI, potions are 1-AP self-drinks from the shared bag, and capture is the only dice roll. Fallen units are gone for good; wounds carry between fights. Towns sell gear and post quests, camps trade food for HP, quest-gated dungeons are Slay-the-Spire room graphs whose elites and bosses are where Epic/Legendary gear enters play, captured enemies are turned in at tavern bounty boards, and the run ends at a boss node (the story's traitor, Mercer Kaine) with a win ledger, or at a game-over ledger when the last unit dies. Progression is gear, not levels. Companions are authored characters recruited through quest scenes, never bought; the player names the MC and later the company. Sources: `specs/2026-03-29-ship-plan-design.md` §1-13; `memory/design_decisions_core.md`; `memory/project_direction_decisions_2026_08.md`; `bible` Pillars.

Player flow (screens, in order):
1. **Title** — rebuild: Continue (present only when the run autosave exists) / New Run (deletes it) / Quit. Shipped: New Game / Load Game (3 slots, disabled when all empty) / Quit. (`phaser/src/ui/screens/TitleScreen.tsx`; save model in §2.14)
2. **Tutorial battle** (first run only, `meta.tutorialSeen`) — 5x5 grid, MC vs one under-statted bandit, state-derived overlay steps. (`specs/2026-03-29` §12; `phaser/src/ui/overlays/TutorialOverlay.tsx`)
3. **Prologue dialogue** (flag `prologue_seen`) over the overworld. (`phaser/src/App.tsx:247-282`)
4. **Overworld** — band + paper map; click a node to travel; GameHud shows region/location/day/food/gold/roster; keys Q quest log, I loadout, Esc pause.
5. **Encounter surfaces mid-hop** — DialogueModal (bottom band, busts), CheckEventModal (stat/class/gold/food checks with "who tries this?" picker), or a battle.
6. **Node quick-action menu** on arrival (M&B style): Enter Town / Inn / Shop / Tavern; Make Camp; Enter Dungeon; Challenge the boss; Continue Travel / Stay Here.
7. **Town** — ledger spread: Inn, Shop, Tavern (rumors, quest board, bounty board listing prisoners). **Camp** — Rest / Scout / Leave. **Dungeon** — StS row graph; combat rooms return to the dungeon; boss room exits it. **Naming beats** — a `NameEntryModal` opens from a quest effect at the guild-registration scene (MC name) and again once a few companions have joined (company name).
8. **Combat** — board + HUD (initiative strip, herald plaque, hand of 5, forecast panel pin-then-confirm, Move/End Turn, Use Item, capture buttons, Tab danger zones, unit detail panel).
9. **Battle end** — Field Report (victory: enemies defeated, survivors, fallen named, gear drop named with rarity, prisoners taken) / Final Entry (game over) / Throne (run complete) with run-stat ledger; Continue / Restart / New Run / Return to Title.
10. **Pause / Quest Log / Loadout** — root-mounted ledger-page modals reachable from any non-title view; pause offers Resume / Settings / Save & Quit to Title (no manual save slots, §2.14).

## 2. Must-have systems and rules

### 2.1 Combat — turns and AP
- Grid 14x10 (tutorial 5x5). Stage-fitted tile pitch: TILE 48 base, even size in [40, 96], play band y 120..560 (5x5 -> 84px, 14x10 -> 42px). (`phaser/src/domain/boardGeometry.ts`)
- **Per-unit initiative**, not team phases: queue = living units sorted by (SPD + slow delta) desc; SPD tie -> party first; then id. Rebuilt from living units at every endTurn (deaths/slows re-sort live); `turn.number` increments when the index wraps. (`phaser/src/systems/turnOrder.ts`; `specs/2026-05-10-combat-hud-initiative-forecast-design.md` §1)
- Each unit's turn: **one free move** (class `startingMov`: lord 5, knight 4, mage 5, bandit 4, thief 6, wolf 6, shield_knight 3; 4-directional BFS through unoccupied non-obstacle tiles; refused if already moved or immobilized) + **AP_PER_TURN = 3** of card plays, item uses (§2.3) and capture (§2.6). (`phaser/src/systems/combatReducer.ts:51-54`, `moveUnit`; `phaser/src/systems/targeting.ts`)
- **endTurn order**: (1) tick the ENDING unit's statuses (DOT, decrement, expire); (2) checkEnd; (3) next unit gets ap = 3 and `hasMovedThisTurn = false` (and its per-turn cover counter cleared, §2.16); (4) ending unit discards its whole hand, next unit draws to **HAND_SIZE = 5**, reshuffling discard into draw with the combat RNG when dry (zero card loss); (5) clear selection. (`combatReducer.ts:219-298`)
- Legality lives in the reducer: bounds, obstacles, occupancy, move range, card range, targetKind, AP. `[DRIFT]` shipped reducer validates only bounds/obstacles/occupancy; range and targetKind are view-only. Rebuild validates everything in the reducer.
- Rebuild rule: the reducer owns the RNG in state and returns the advanced state; it never accepts a throwaway RNG. `[DRIFT]` shipped `reduce(state, event, rng)` discards the RNG it is handed: the `capture` case is the ONE place the caller's `_rng` is consumed (`combatReducer.ts:744`) and the returned state does not write `rng` back (`:758-761` spreads only `units`), so a failed capture re-rolls identically until a draw happens; `planTurn(state, createRng(state.rng), unitId)` (`BoardScene.ts:1189`) advances a throwaway RNG too. Every case that rolls writes `state.rng`; AI planning is a pure function of (state, state.rng).
- Reducer emits SEMANTIC events (DamageDealt, Healed, StatusApplied, UnitMoved, UnitDied) with no millisecond values; timing belongs to the view. `[DRIFT]` shipped emits PlayTween 250ms / HitFlash 80ms / ShakeCamera 0.005 200ms when total damage >= 10.

### 2.2 Combat — damage, armor, forecast
- No hit/miss/crit/doubling/weapon triangle anywhere. Capture is the ONLY random roll in combat. (`specs/2026-03-29` §1)
- Physical: `DMG = card.base + STR + empower − floor(DEF/2) − terrainDefBonus`; Magic: `card.base + MAG + empower − floor(RES/2) − terrainResBonus`; min 0. `damageStat` may be str|mag|skl. Heals use MAG only. Typical L1 hits land 4-8 against party HP lord 26 / knight 32 / mage 22 and enemy HP wolf 14 / bandit 18 / bandit_archer 16 / thief 16 / shield_knight 30 / alpha_wolf 38 / warlord 46 (`classes.json` startingHp). (`specs/2026-03-29` §2; `combatReducer.ts:437-497`; `damage.ts:107-118`)
- `[DRIFT]` terrain DR is in the spec formula and in `computeForecast(terrainDr)` but every caller passes 0 and no battle grid has terrain. Decide (see §9); if terrain exists, apply it in the reducer.
- **Armor is a breakable shield**: physical -> armor absorbs first, overflow to HP; magic -> `floor(amount/2)` hits armor (leak to HP), `ceil(amount/2)` pierces to HP; hpLost clamped to current HP; amount <= 0 is a no-op. Poison is armor-piercing; burn uses the magic split. Mages/Clerics start at 0 armor; armor resets each battle. (`phaser/src/systems/damage.ts:23-49`; `specs/2026-05-10-combat-hud` §2)
- `[DRIFT]` shipped armor never decays within a battle and stacks uncapped (knight_fortify +5/turn forever; steel_tower_shield_fortress 11). Armor lifetime is an owner question (§9).
- **Forecast == applied**: one pure `computeForecast/applyDamage` feeds both the reducer and the HUD; breakdown terms baseTerm/statTerm/drTerm/terrainDr/hpLost/armorLost/predicted/lethal/heal. (`damage.ts`; `phaser/tests/unit/systems/forecastVsApplied.test.ts`)
- Riposte: a foe with riposte that takes physical damage > 0 from an orthogonally adjacent attacker deals `stacks` HP directly back (ignores armor), not consumed per hit. Shipped hand-codes it inline (`combatReducer.ts:478-496`) while `StatusEffectDef` declares `onApply/onTurnStart/onDamageTaken/onDamageDealt/onTick/interactsWith` hooks that the reducer never calls (only `onTurnEnd`, `:119-121, :304-306`) — rebuild either routes damage through the hooks or deletes them; never ship decorative interfaces.
- **Damage redirect (cover) is a first-class step**: before DR is computed for a target, one pure `resolveCoverTarget(state, attackerId, targetId) -> UnitId` may swap the target (Oak's Genatsvale, §2.16); DR then uses the PROTECTOR's DEF/RES and `FloatDamage` renders on the protector's tile. The enemy AI scorer, the forecast panel (`useForecastPreview.ts`/`ForecastPanel.tsx`) and the headless sim (`scripts/cli/play.ts`) all call the same function or they lie. Nothing redirects damage today: "Cover" cards (`iron_tower_shield_cover`, `knight_bulwark`, `knight_taunt`) are armor + taunt, and taunt is only an AI target filter (`enemyAI.ts:77-93`).

### 2.3 Combat — cards, targeting, effects, consumables
- Card: `{id, name, apCost 0-3, range{min,max}, targetKind enemy|ally|self|tile|all_enemies|all_allies, aoeRadius 0-2, weaponType null|sword|lance|axe|bow|crossbow|tome|staff|greatsword|dagger|shield, damageStat, effects[]}`. Range = manhattan in [min,max] from the source tile, obstacle tiles excluded, no LOS. AOE = manhattan radius around the chosen tile, center included; MUST resolve on every tile in the radius (`[DRIFT]` BoardScene dispatches only the clicked tile). `all_enemies`/`all_allies` need a real runtime path (none exists). (`phaser/src/domain/card.ts`; `targeting.ts`; `research/gear-content-deviations.md`)
- Effect primitives, as a typed discriminated union with an explicit target selector (`self|target|ally|area`) and an exhaustive switch: Damage{base, damageType, armorPiercing}, Heal{amount}, ApplyStatus{effectId, value, turns, splash:'adjacent'}, RemoveStatus{kind armor|debuff, amount|all}, Move{distance}, GrantArmor{amount}, DrawCards{count, gainAp}, GainAp{amount}. A content lint fails on any param the engine does not consume. `[DRIFT]` shipped ignores GainAp.target, GrantArmor.magic/scalesWithShield, RemoveStatus.all (frost_axe_shatter removes 0), Move.distance (lord_charge/bandit_charge never move); RemoveStatus was a no-op for months; beneficial riders on enemy-target cards route to source by inference (brace family once armored the ENEMY). (`combatReducer.ts:498-601`; `research/gear-content-deviations.md`)
- Spec mechanics the catalog wants but the engine lacks (27 cards approximated): lifesteal, true armor-ignore, cover/redirect, self-centred enemy AOE, heal-over-time, conditional damage (vs burning / <25% HP), teleport, untargetable, line pierce, damage mark, ranged-only empower, execute. Either implement them and restore the JSON to spec at the same time, or author only from supported primitives. Never ship silent approximations. Cover/redirect is no longer optional — Genatsvale (§2.16) needs it. The Epic/Legendary set is where the rest bite hardest (§2.13): shadowfang `shadow_step` has no teleport and `vanish` no untargetable; doombow `piercing_shot` no line, `death_mark` is poison 5/2t not a +5 mark; excalibur `holy_slash` no heal, `judgment` no execute, `radiance` no party heal; frost_axe `frozen_ground` is single-target not 3x3. Atlas story 456's "unique effects (teleport, mark, lifesteal, line pierce)" AC is not met — the legendaries are stat-sticks. Implement Teleport, Mark, Lifesteal, LinePierce, Untargetable or accept flat numbers; decide once.
- Tile-target cards must not apply statuses to allies caught in the radius (`[DRIFT]` shipped does). Damage on tile AOE is already foe-only.
- Play resolution: refuse if `ap < apCost`; move the card to discard FIRST; targets = LIVING unit per tile; expand AOE; split foe/ally by `Unit.team`; resolve effects in order; apply quiver mods to foes; deduct AP (floor 0); checkEnd. (`combatReducer.ts:345-683`)
- **Consumables (ruling — no owner question):** potions are **1-AP combat plays, self-target, drunk by the active party unit straight from the shared party bag**. No overworld/camp item-use UI; enemies never use them. Healing Potion = heal 10 HP, single use, 30g/15g. Power Elixir = +3 AP to the drinker this turn (net +2 after the 1-AP use), single use, 80g/40g; tune to +2 (net +1) if playtests show burst kills — it is deliberately stronger than `lord_inspiring_strike`/`lord_command` (2 AP for +1 AP, net −1) and costs an Iron Sword. A 10-HP self heal for 1 AP is on-curve with `heal_staff_heal` (8 HP / 1 AP) and ~40% of a party unit's max HP; its job is needing no healer. **Drop Vulnerary (80g, 10 HP x3) and Elixir (500g, full heal x3)** — the Godot multi-charge model (`godot/data/items/item_catalog.json:153-182`: vulnerary heal 10 max_uses 3; elixir heal 999 max_uses 3) that phaser never ported (no `uses`/`charges`/`effect` field exists in `schemas/item.ts:12-31`; one item = one drink). This is exactly the rule the only implementation ever written used — Godot commit `1780e56` `use_quick_slot_item` (cost 1 AP, refuse at 0 AP, heal the drinker only, sentinel 999 = full heal, consumed on last charge, auto-end turn when AP hits 0 with an empty hand) — and exactly `specs/2026-03-22-mechanics-redesign` §3 "In-Combat Actions (1 AP each): Use consumable", minus quick slots (cut by ship plan §10 line 360, which removed the container and the function without writing a replacement rule; its stated reason was weapon swapping, not potions). Deleted with the quick-slot system in Godot `e95c225`; the phaser port (`408826e`, parity spec line 80) created `kind:'potion'` with no mechanic (`domain/item.ts:12` admits "use action lands later"). Shipped: `RunAction` has no `useItem` (`runStore.ts:68-118`), `CombatEvent` has no item event and `startBattle.payload` never receives the bag (`combatState.ts:54-86`), HUD buttons are Capture/Move/End Turn only (`CombatHud.tsx:156-161`), loadout shows a dead "+N consumable" caption (`PartyLoadoutModal.tsx:684`).
- Consumable contract: item data gains `effect: {kind:'Heal', amount:10}` / `{kind:'GainAp', amount:3}` reusing the card effect kinds (no new primitives; `Heal` and `GainAp` already exist in `domain/card.ts:7-15` and `combatReducer.ts:552/581`); `startBattle.payload.consumables: ItemId[]` mirrored on `CombatState.consumables` (AI ignores it); new `CombatEvent {type:'useItem', payload:{unitId, itemId}}` — reject if `ap < 1`, if `unitId` is not the active party unit, or if the item is not in `consumables`; else `ap -= 1`, apply the effect to `unitId` only, remove one instance, emit the existing `FloatDamage{damageKind:'heal'}`, same auto-end-turn check as `playCard`; `BattleResult.consumedItems: ItemId[]` and `applyBattleResult` removes them from `inventory.items` first-match by id (like `consumeFoodPerHop`, `runStore.ts:620-628`) — combat never mutates the run bag directly; HUD `UseItemBtn` beside Move/End Turn listing bag potions with counts, greyed at 0 AP. Out-of-combat healing already covers the map (camp Rest 20%, dungeon rest 30%, Inn full, §2.10-2.11) — keep in-combat potions the mid-fight lever and Rest/Inn the between-fight lever; no camp "drink potion" button.

### 2.4 Statuses
All fixed numbers, no resist roll. (`specs/2026-03-29` §9; `phaser/src/systems/statusEffects.ts`)
- **Poison**: X dmg at end of victim's turn for N turns, armor-piercing, non-stacking (reapply = max stacks, max duration).
- **Burn**: same tick, magic split, STACKS additively, duration = max.
- **Slow**: −stacks SPD in initiative for N turns, refresh. **Immobilize**: MOV 0, refresh.
- **Taunt**: rusher/tank/archer AI must target taunters. **Riposte**: §2.2. **Empower**: next Damage card +stacks, consumed on use.
- DOT death flips phase to VICTORY/DEFEAT at the tick.
- A 1-turn self-buff played on the owner's turn must survive the following enemy phase. Rebuild with an explicit expiry model ("expires at start of owner's next turn"), not the shipped `ActiveStatus.fresh` flag hack (`combatReducer.ts:112-150, 417-432`) — though the `fresh` idea is exactly what a stance-style passive needs; keep the semantics, encode them in data.

### 2.5 Enemy AI (authored, not cards)
- Enemies do NOT play their decks (owner decision, `memory/design_decisions_core.md`). Per-class profile `{role rusher|archer|healer|tank, movement, preferredRange, actions[{range, amount, damageStat, weight, situation always|self_low_hp|target_low_hp|ally_wounded, aoeRadius}]}`. Situations: self/target HP < 40%; ally_wounded = hp < max. (`phaser/src/data/schemas/enemyAI.ts`; `phaser/src/systems/enemyAI.ts`)
- Targeting: rusher/tank -> taunters else min(hp x 100 + distance), desired tile = free orthogonal neighbour closest to self; archer -> taunters else nearest party unit, desired tile at preferredRange (2-3) min move cost; healer -> lowest-HP-fraction wounded ally in range (1-2) else the furthest party unit. Expected-damage scoring must go through `resolveCoverTarget` (§2.2).
- Movement: walk up to `movement` steps via a BFS distance field flooded from the destination (living units are walls, visited tiles banned) — never axis-greedy.
- Action pick: filter by post-move range + situation, weighted `rng.nextInt` drawn from `state.rng` and written back (no throwaway `createRng(state.rng)`, §2.1). Enemy actions MUST be able to apply statuses/buffs (poison, burn, alpha howl) — `[DRIFT]` shipped schema is attack|heal only, so Thornwood poison and Ashfall burn never fired from enemies. Enemies spend 1 synthesized action per turn today (budget is an owner question, §9).
- Spawn within one move + attack of the party on turn 1 (bandits col 8-9 vs party col 0-2; an 11-tile gap read as "broken"). (commit `94bb909`)

### 2.7 Gear-as-deck, hand slots, bag

## 7. Bugs and lessons the rebuild must design out

Each: what happened -> the structural rule.
1. **AP never reset after turn 1** shipped past 527 green unit + 22 e2e tests because every harness resolved battles in one turn (commit `a58fe8d`) -> every turn/round/cycle system ships with a test that runs >= 3 FULL cycles asserting per-cycle restoration (AP = 3, hand = 5, reshuffle with zero card loss, status expiry, cover counter cleared); a manual full-run playtest precedes any "beta".
2. **Two months of "balance" chased 0%-win / 100%-stalemate sim numbers that were three engine bugs** — corpse shadowing, axis-greedy melee AI stall, dungeon party spawned off-board (commit `f4c4bef`) -> a stalemate/0%-win sim result is an engine smoke alarm: reproduce one battle by hand first; any round-cap hit fails loudly with a per-round state dump, never a tidy "STALEMATE" statistic.
3. **Corpse shadowing** — dead units kept `position`, so a live enemy on a corpse was immune to single-target cards -> corpses leave the board (or live in a separate list); no tile->unit lookup without an alive filter.
4. **Melee AI froze** when one party unit stood on the sole approach tile -> BFS distance-field stepping with a banned-revisit set; never axis-only.
5. **Dungeon party never positioned** (`position: null` from the run store) -> `startBattle` asserts every unit has a position; one seeder.
