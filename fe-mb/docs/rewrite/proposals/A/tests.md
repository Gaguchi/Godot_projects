# Proposal A — acceptance tests → vitest files

Every bullet in brief §10 maps to a named `it(...)` in one file. All engine
tests run in `environment: node` (vite.config.ts already sets it); DOM
tests exist only for modal FLOWS (§8.12) and live under `tests/unit/ui/`.
Fixtures: `tests/fixtures/env.ts` builds an `EngineEnv` from the real
content (`buildContent`) and exposes `envWith({ knobs })` to flip rules;
`tests/fixtures/battles.ts` exposes `seedStub(seed)`, `seedWithOak(seed)`,
`seedBoss(seed)`; `tests/fixtures/runs.ts` exposes `runAt(nodeId, seed)`.

Two harness helpers make multi-turn coverage the default (§7.1):

```ts
playRounds(state, n, policy)      // drives the runtime through n FULL initiative wraps via drain(); asserts per-cycle restoration
autoBattle(state, policy, cap?)   // party greedy policy + enemy pumps until terminal; throws with a state dump at rules.combat.roundCap
```
